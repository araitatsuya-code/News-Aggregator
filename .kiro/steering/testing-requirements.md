# テスト要件とベストプラクティス

## 実装完了後のテスト実行

### 必須要件
- **実装完了後は必ずテストを実行してパスすることを確認する**
- テストが失敗した場合は、実装を修正してテストをパスさせる
- 新しい機能を実装する際は、対応するテストも作成する

### テスト実行コマンド
```bash
# 特定のテストファイルを実行
npm run test -- --testPathPattern=ComponentName.test.tsx --watchAll=false

# 全テストを実行
npm run test -- --watchAll=false

# 診断ツールでコンパイルエラーをチェック
# getDiagnosticsツールを使用してファイルの問題を確認
```

### テスト作成のガイドライン

#### アクセシビリティテスト
- WCAG準拠のテストを含める
- キーボードナビゲーションのテスト
- スクリーンリーダー対応のテスト
- カラーコントラストの検証
- モーション設定の対応テスト

#### 必要な依存関係
```bash
npm install --save-dev jest-axe @testing-library/jest-dom @testing-library/user-event
```

#### テストファイルの構造
```typescript
// テストファイルの基本構造
describe('ComponentName', () => {
  describe('アクセシビリティ基準', () => {
    test('WCAG準拠のアクセシビリティ違反がないこと', async () => {
      // jest-axeを使用したアクセシビリティテスト
    });
    
    test('適切なARIA属性が設定されていること', () => {
      // ARIA属性の検証
    });
  });
  
  describe('キーボードナビゲーション', () => {
    test('Enterキーでクリックイベントが発火すること', () => {
      // キーボード操作のテスト
    });
  });
  
  describe('エラーハンドリング', () => {
    test('無効な入力でもエラーが発生しないこと', () => {
      // エラーケースのテスト
    });
  });
});
```

### テスト実行のワークフロー

1. **実装完了時**
   - 関連するテストファイルを実行
   - 全テストがパスすることを確認
   - 失敗したテストがある場合は修正

2. **新機能追加時**
   - 新機能に対応するテストを作成
   - 既存のテストが影響を受けていないか確認
   - 回帰テストの実行

3. **バグ修正時**
   - バグを再現するテストを作成
   - 修正後にテストがパスすることを確認
   - 関連する機能のテストも実行

### パフォーマンステスト

#### 重要な指標
- First Load JS: 130KB以下を維持
- コンポーネントのレンダリング時間
- アクセシビリティ機能のパフォーマンス影響

#### 測定方法
```typescript
// パフォーマンステストの例
test('コンポーネントが高速にレンダリングされること', () => {
  const startTime = performance.now();
  render(<Component />);
  const endTime = performance.now();
  
  expect(endTime - startTime).toBeLessThan(100); // 100ms以下
});
```

### 継続的インテグレーション

#### 自動テスト実行
- プルリクエスト作成時
- マージ前の必須チェック
- デプロイ前の検証

#### テストカバレッジ
- 新しいコンポーネントは80%以上のカバレッジを目標
- 重要な機能は100%のカバレッジを維持
- アクセシビリティ機能は必須テスト対象

### トラブルシューティング

#### よくある問題と解決方法

1. **act()警告**
   - 状態更新を伴うテストでact()を使用
   - userEventライブラリの適切な使用

2. **非同期処理のテスト**
   - waitFor()を使用した適切な待機
   - タイムアウト設定の調整

3. **モック設定**
   - 外部依存関係の適切なモック
   - ブラウザAPIのモック設定

### 品質保証チェックリスト

実装完了時に以下を確認：

- [ ] 全テストがパスしている
- [ ] アクセシビリティテストが含まれている
- [ ] エラーハンドリングがテストされている
- [ ] エッジケースがカバーされている
- [ ] パフォーマンスが基準を満たしている
- [ ] TypeScriptエラーがない
- [ ] ESLintエラーがない
- [ ] コンソールエラーがない
